# 银行柜面现金长短款复核与缴回系统

柜员结柜登记实盘现金 → 主管复核差额 → 长款待认领 / 短款缴回或责任说明 → 财务确认全部未处理事项后关闭营业日。

## 一条命令本地启动

```bash
./start.sh
```

脚本会安装依赖、初始化 SQLite 并写入种子数据，然后同时启动：

- 后端（NestJS + Prisma + SQLite）：http://localhost:3000/api
- 前端（React + Vite）：http://localhost:5173

种子用户（页面右上角切换，请求头 `x-user-id` 标识操作人）：

| 用户 | 角色 |
| --- | --- |
| 张敏 / 李强 | 柜员 TELLER |
| 王芳 | 主管 SUPERVISOR |
| 赵磊 | 财务 FINANCE |

## 运行验证测试

```bash
npm test
```

16 个用例覆盖：金额核对（面额计算、机器/手工冲突）、复核流程（自复核禁止、退回再提交）、
财务回执幂等（重复回执不重复确认/冲销）、并发结柜（同班次只成功一次、两人同时结柜各自入账一次）、
跨日差额归属（事后找到现金记在原营业日）、营业日关闭校验。每个用例都断言账目恒等式
`Σ账本条目 == 当前差额 - Σ已确认处置`，确保调整前后账目一致。

## 业务规则

- **结柜登记**：按面额填写应有/实盘数量，系统计算长款（实盘>应有）或短款；同一柜员同一营业日同一班次只允许一张结柜单（数据库唯一约束，并发提交只成功一次）。
- **机器 vs 手工**：点钞机总数与手工盘点不一致时标记冲突并提示复核，系统不自动采信任一方；须柜员通过「修正记录」确认数量后主管才能复核通过。
- **复核**：仅主管可复核，且不能复核本人结柜单；复核通过生成立项处置单（长款→待认领，短款→缴回或责任说明）；退回的结柜单可通过修正记录重新提交。
- **调整记录**：重复结柜修正、跨班交接差异、事后找到现金全部通过调整记录处理；跨日录入时保留差额归属营业日（账本条目记在原营业日），结柜页可展开每次修正的面额快照。
- **财务回执**：回执号唯一，重复回执幂等返回原结果，不会重复确认或重复冲销；冲销只能针对已确认的处置单。
- **关账**：存在未复核、未确认或机器/手工冲突未解决的事项时，财务不能关闭营业日。

## 目录结构

```
server/            NestJS 后端
  prisma/          SQLite 数据模型与种子
  src/             结柜/复核/调整/财务/营业日/账本服务与控制器（含点钞机、财务接口本地模拟）
  test/            vitest 验证测试（独立测试库）
web/               React 前端（结柜盘点 / 主管复核 / 财务与营业日）
start.sh           一条命令本地启动
```

## 主要接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | /api/closings | 柜员结柜登记（面额明细） |
| GET | /api/closings/mine · /pending-review · /:id | 查询结柜单 |
| POST | /api/closings/:id/adjustments | 登记调整（修正/交接/找到现金） |
| POST | /api/reviews | 主管复核（通过/退回，短款可选缴回或责任说明） |
| GET/POST | /api/finance/pending · /confirm · /reverse · /receipts | 财务确认/冲销/回执接收（幂等） |
| POST | /api/days/close · /open-next，GET /api/days/:id/report | 营业日关闭/开启/报告 |
| POST | /api/mock/cash-machine/count | 本地模拟点钞机 |
